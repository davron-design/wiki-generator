Beginner's Guide

Building the Agentic Mind.

A knowledge base that grows with every project.

A friendly walkthrough for setting up an AI-powered knowledge base with Claude Code — and collaborating on it with your team. No terminal. No coding.

Get Started → View on GitHub
01
Get Started

Set it up in 10 minutes.

You'll need the Claude Code desktop app and about 10 minutes. That's it.

1

Create a folder for your wiki

Pick a spot on your computer — your Desktop is fine. Create a new folder and name it whatever you want: My Wiki, Gardening Notes, Work Knowledge Base.

That folder is the home of your wiki. Everything will live inside it.

2

Open the folder in Claude Code

Launch the Claude Code desktop app and open the folder you just created. You should now see an empty project with a chat box ready to go.

3

Install the wiki generator skill

Paste this prompt into Claude Code:

Please download the repo at https://github.com/davron-design/wiki-generator and install it as a project-scoped skill in this folder. Put the skill files under .claude/skills/wiki-generator/ so the skill only applies to this project. Once it's installed, list the skills so I can confirm it's ready to use.

If Claude asks for permission, just Always Allow. You only need to do this once per wiki.

4

Build your wiki project

In Claude Code, type:

/wiki-generator

Claude will create three folders for you:

  • raw/ — where you drop source material (articles, notes, research)
  • wiki/ — where the polished knowledge base lives
  • output/ — where reports and query results show up

It also installs two companion skills — raw-compile and audit-wiki — automatically.

5

Add material to raw/

This is where you feed your wiki. Open the raw/ folder and drop in any material you want included — articles, notes, research clippings, transcripts.

Add as many files as you want. Don't worry about organizing them — that's Claude's job.

6

Compile the raw material

In Claude Code, simply say:

compile

Claude will read every file in raw/, group the material by topic, write clean wiki articles into wiki/, link them together with [[wiki links]], and archive the compiled raw files so you know what's been processed.

Sit back — this part is automatic.

7

Audit your wiki

Once your wiki is built, check it for gaps or inconsistencies. In Claude Code, say:

audit

Claude will scan the wiki and produce a numbered audit report in output/_audits/. The report points out missing cross-links, thin topics, and inconsistencies between articles.

The audit is report-only by default — it won't change anything until you say so.

02
Work Together

Collaborate with your team.

Want a small team to build the same wiki together? Use GitHub Desktop as the syncing layer. No terminal, no coding.

What You'll Need (per person)
  • The Claude Code desktop app — you already have this
  • The GitHub Desktop app — desktop.github.com
  • A free GitHub account — github.com/signup
One-Time / Team Lead

Set up the shared repo

  1. Go to github.com/new and create a new repository (e.g. team-wiki). Keep it Private if your material is sensitive.
  2. Open the wiki folder in GitHub Desktop → File → Add Local Repository → pick the folder → click Publish repository.
  3. In the repo's Settings → Collaborators on github.com, invite your teammates by username or email.
One-Time / Each Teammate

Get a synced copy

  1. Install GitHub Desktop from desktop.github.com and sign in.
  2. Accept the email invitation from the team lead.
  3. In GitHub Desktop, click Clone a repository → pick your team's wiki → choose where to save it.

You now have a synced copy of the wiki on your machine.

Daily / Everyone

Pull, work, push

Before you start working:

  1. Open GitHub Desktop → Fetch origin → Pull origin to grab the latest changes.
  2. Open the wiki folder in Claude Code and work as usual — drop files into raw/, say compile, ask the wiki questions.

When you've made changes you want to share:

  1. In GitHub Desktop, you'll see all your changed files on the left.
  2. Type a short summary at the bottom (e.g. "Added gardening notes").
  3. Click Commit to main, then Push origin.

Your teammates can now Fetch → Pull to receive your changes.

Tips

Habits that prevent conflicts

  • Pull before you start. Push when you finish. That habit prevents most conflicts.
  • If two people edited the same article at the same time, GitHub Desktop will guide you through merging.
  • Everything is version-controlled — you can roll back any change from GitHub Desktop's History tab.
03
Advanced Collaboration

Pull Requests for bigger teams.

The "everyone pushes to main" flow above works for small, trusted teams. As your group grows — or when changes need a second pair of eyes before going live — switch to Pull Requests.

What's a Pull Request?

Think of a Pull Request (PR) as a draft change proposal. Instead of pushing your edits straight into the shared wiki, you save them on a personal "side track" (a branch) and ask a teammate to review them. Once approved, the change is merged into the main wiki — and everyone else pulls it down as normal.

It's the digital equivalent of "let me show you this before I publish it."

Two roles — Maintainers and Contributors

PRs introduce a split between two roles:

RoleWhoWhat they do
MaintainerTeam lead (1–2 people)Reviews PRs, approves or requests changes, merges into main, manages access
ContributorEveryone elseEdits the wiki on their own branch, opens a PR, responds to review feedback

The maintainer is not the only one who can edit the wiki — contributors do all the writing. The maintainer's job is to be the gatekeeper of main, making sure nothing inconsistent or accidental lands in the shared copy.

One-Time / Maintainer

Turn on branch protection

To require PRs (instead of letting anyone push directly to main):

  1. Go to your repo on github.com.
  2. Click Settings → Branches.
  3. Under Branch protection rules, click Add rule.
  4. Branch name pattern: main
  5. Check Require a pull request before merging.
  6. Click Create.

From now on, every change — even the maintainer's own — flows through a PR.

Daily / Contributor

The PR workflow

1. Start a branch before editing. In GitHub Desktop, click the Current Branch dropdown → New Branch → name it after your change (e.g. add-gardening-notes) → Create branch.

2. Edit as usual. Open the folder in Claude Code, drop files into raw/, say compile. Your changes are isolated to your branch — main is untouched.

3. Commit and push your branch. Write a commit message → Commit to <your-branch> → Publish branch (first time) or Push origin (after that).

4. Open the Pull Request. GitHub Desktop shows a Create Pull Request banner — click it. A browser tab opens on github.com. Add a short description of what changed and why → Create pull request.

5. Wait for review. Your maintainer gets notified. They'll either:

  • Approve and merge — your change goes live, and everyone else can pull it.
  • Request changes — they leave comments; you edit on the same branch, commit, and push. The PR updates automatically.
Daily / Maintainer

Reviewing a PR

  1. Open the PR on github.com (you'll get an email notification).
  2. Read the description and click the Files changed tab to see exactly what changed.
  3. Leave comments on specific lines if needed, or approve the PR.
  4. When ready, click Merge pull request → Confirm merge.
  5. Click Delete branch (the button appears after merge) — keeps the repo tidy.
Tips

Keep PRs healthy

  • Keep branches short-lived. Open a PR, get it merged, delete the branch. Long-running branches drift from main and become painful to merge.
  • One PR per topic. Don't bundle "added gardening notes + fixed typos + restructured wiki" into one PR — split them. Smaller PRs review faster and are easier to revert.
  • Write clear PR descriptions. A one-line title plus 2–3 sentences explaining what and why makes review much faster.
04
Viewing in Obsidian

Browse your wiki visually.

Claude builds the wiki. Obsidian — a free markdown app — gives you a clickable, searchable, visual way to read it. Same folder. No sync needed.

What's Obsidian, and why use it?

Claude Code is great for building the wiki — compiling raw material, writing articles, running audits. But it's not designed for browsing what you've built.

Obsidian fills that gap. It's a free markdown reader that natively understands [[wiki links]] — the same link style Claude already writes into every article. That means:

  • Click any [[link]] in an article and jump to it.
  • Search across the whole wiki instantly.
  • See a graph view showing how topics connect.
  • Read your wiki on your phone or tablet too (optional).

Obsidian doesn't change your files. It just reads the same folder Claude is writing to.

1

Download Obsidian

  1. Go to obsidian.md.
  2. Click the big Get Obsidian button.
  3. Pick the installer for your computer (Mac, Windows, or Linux) and install it like any other app.

Obsidian is free for personal use — no account or sign-up required.

2

Open your wiki folder as a vault

In Obsidian, a "vault" is just a folder full of markdown files. Your wiki folder is already exactly that.

  1. Launch Obsidian.
  2. On the welcome screen, click Open folder as vault.
  3. Pick the wiki folder you created earlier (the one Claude Code is working in).
  4. Click Open.

Obsidian scans the folder and shows every markdown file in the left sidebar.

Tip: You can point Obsidian at the whole project folder (so you also see CLAUDE.md, raw/, etc.), or just the wiki/ subfolder if you only want to browse the polished knowledge base. Either works — pick whichever feels less cluttered.
3

Start at the master index

Your wiki has a built-in entry point.

  1. In the left sidebar, open wiki/_master-index.md.
  2. You'll see a table of every topic in your wiki.
  3. Click any [[link]] in the table to jump to that topic's index.
  4. From there, click into any article.

This is the same path Claude follows when answering questions — now you can walk it yourself.

4

Try the Graph View

This is the fun part.

Every article is a node. Every [[link]] between articles becomes an edge. Hover any dot.

  1. Click the graph icon in the left sidebar (it looks like three connected dots), or press Ctrl/Cmd + G.
  2. You'll see every article in your wiki as a node, with lines connecting articles that link to each other.
  3. Click any node to jump straight to that article.

The graph is a quick way to spot orphaned articles (nothing links to them) and clusters (topics that are tightly connected). It's also a nice visual gut-check on how your wiki is growing.

5

Use search

Press Ctrl/Cmd + Shift + F to open the search panel. Type anything — Obsidian searches across every article instantly.

For quick file-name lookups, press Ctrl/Cmd + O and start typing an article name.

How Obsidian and Claude Code Work Together

You don't have to pick one. They share the same folder.

TaskUse
Drop new material into raw/Either (Obsidian or Finder)
Compile / audit / ask the wiki questionsClaude Code
Browse, search, follow links, read articlesObsidian
Edit an article by handEither

A common rhythm:

  1. In Claude Code, say compile to bring new material into the wiki.
  2. Switch to Obsidian to read what Claude wrote, follow the links, and check the graph.
  3. Spot something thin or missing? Back to Claude Code and say audit.
